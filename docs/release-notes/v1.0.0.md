# WaferEdge 1.0.0

The first release: an in-line wafer-map watchdog at the equipment edge, from the SECS-II
decoder to the lot hold, with every number measured and reproducible (README).

## What is in it

- **Signatures on the wafer map**: die and fail counts by zone, sector and ring (scalar and
  AVX2, bit-for-bit equal), connected fail clusters, a Hough search for scratches and a
  join-count randomness test, feeding an explainable rule classifier (ADR-0005).
- **The same signatures on the GPU** (CUDA, sm_86), batched from one upload, with CUDA Graphs
  and packing overlapped with the GPU work; equal to the CPU on every real map (docs/gpu.md).
- **FabEye's CNN on WaferEdge's own inference engine**: a GEMM ladder up to tensor cores,
  implicit-GEMM convolutions, fusion, fp16 and int8, keeping FabEye's macro-F1 and conformal
  coverage (docs/inference.md).
- **The equipment protocol**: SECS-II codec (zero-copy decode), HSMS over TCP on Asio
  coroutines, a GEM subset; 0 allocations per message; fuzzed in CI (docs/secs.md).
- **The edge pipeline**: tool emulator, edge host with lock-free SPSC rings and an
  allocation-free hot path, pluggable detectors, batching by size or deadline, a per-lot
  and an optional cross-lot hold rule; open-loop latency measurement with an HDR-style
  histogram (docs/pipeline.md).
- **The closed-loop result** on WaferLens's 13 spatial excursions, against WaferLens's batch
  alarm and against no hold (ADR-0017, ADR-0018).
- **Python**: features, signals, the rule classifier and the clusters on NumPy arrays, read
  in place (docs/python.md, ADR-0019).

## Results (from the README)

- Sort result → decision: 0.3–0.5 ms median, p99 0.7–2.3 ms at 1,000–5,000 wafers/s, CPU
  rules, laptop.
- Closed loop: all 13 excursions held; first patterned wafer at sort → hold 2.0 h median
  with 2 of 5 or 3 in 24 h (WaferLens's alarm: 3.0 h), 8.1 h with the default 3 of 5.
- Macro-F1 on WM-811K's test lots: rules 0.655, FabEye's CNN 0.858.
- GPU, all three signatures: ahead of the whole CPU from ~4 maps a batch with CUDA Graphs,
  ~9× it at large batches.

## Assets

- `waferedge-1.0.0-linux-x86_64.tar.gz`: the command-line tools (Ubuntu 24.04, GCC 13,
  CPU build; the CUDA tools need a local `cmake --workflow --preset cuda`), `config/`, and
  the build information.
- `waferedge-1.0.0-*.whl` (CPython 3.12, linux_x86_64) and `waferedge-1.0.0.tar.gz` (sdist).

## Limitations

Simulated fab data for the closed loop; GPU tests run locally, not in CI; measured on one
laptop under WSL2; a subset of SEMI E5 / E30 / E37, not certified.
